# TOG 测试细则

> 通用的 E2E 纪律在工作室 skill `shiyawase-e2e`；命令与分层总表在 `docs/PROJECT_PROFILE.md`。
> 这份是 TOG 特有的覆盖面与陷阱。

## 沙箱里怎么跑浏览器套件

```sh
NODE_USE_ENV_PROXY=1   PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome   UI_E2E_PASSWORD=… npm run test:ui-e2e
```

`UI_E2E_PASSWORD` 必填（**绝不把真实密码写进代码**）；`UI_E2E_URL` / `UI_E2E_EMAIL` 可选。
脚本自带一个进程内反向代理，所以在有出口代理的环境下浏览器也能通。

**只在没有别的运行在跑的时候跑**（`deploy.yml` 里的 API E2E 也算）—— 两个运行会抢同一批线上 fixture。

## 三条最容易翻车的纪律

1. **登录检查必须语言无关。** 等 `.sidebar`（每个已登录页都有、登录页没有），
   **不要等某个翻译过的标题** —— 教会把界面切成中文那天，整套测试会在第一个检查点死掉，
   90 秒重试之后报出来像是登录坏了。
2. **语言 pin 只在登录后抓一次。** 套件读英文标签，所以登录后立刻把账号语言 pin 成 `en`，
   并在 `finally` 里还原教会自己的选择（日常是简体中文）。
   **后面的语言模块绝不能重读它** —— 否则还原时交回去的是 pin 而不是教会的真实设置。
3. **构建戳守卫。** 套件打的是**已部署的站点**。旧脚本打到新部署，会把「选择器搬家了」报成失败。
   用 `UI_E2E_EXPECT_BUILD`：脚本等 `/api/version` 报出那个构建，被新部署超车就 **exit 0 跳过**。
   **绝不要靠放宽选择器来「修」红灯** —— 先确认它到底测的是哪个构建。

## Fixture 与清理

前缀 `ZZ_UITEST_` / `E2E`。收尾**按前缀扫全库删掉**，不只删本次注册的 —— 上一次崩掉的残留会一直堆积。
崩溃路径上也跑。**残留 = 失败**，不管断言说什么。
套件改过的东西（模块开关、教会主题、界面语言）都要在 `finally` 里还原。

**破坏性动作只在本次创建的数据上做。** 全选往返只在**本次创建的聚会列**上驱动 ——
绝不在主日那一列上做，那是会众真实的出席记录，删了就是真删了。
