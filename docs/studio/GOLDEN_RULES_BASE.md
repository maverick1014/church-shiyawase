# 通用金律 / Golden Rules — Base

> **正本。** 产品仓库同步副本到 `docs/studio/GOLDEN_RULES_BASE.md`。
> 版本：`v1.0.0` · 源：`maverick1014/website:studio/standards/GOLDEN_RULES_BASE.md`
>
> 四个产品**全部**适用。各仓库 `docs/golden-rules/{backend,ui}.md` 在此之上加自己的规则，
> **只能加严，不能放宽**。评审时引用编号：`S3 违规`。

---

### S0 — 推之前必须本地验证过
CI 不是用来发现「这改动能不能跑」的地方。推之前跑该项目 `PROJECT_PROFILE.md` 里列的
静态检查 + 单元测试 + build，并**读输出**，不是瞄一眼 exit code。

### S1 — 绝不直接推 `main`
一律 `claude/<feature>-<hash>` 分支 → PR → merge commit。合并后把分支重置到最新 `main`。

### S2 — 权限在服务端强制，UI 只是反映
任何访问控制、租户隔离、角色判断，**先在服务端拦**，再在 UI 隐藏。
一个「点了只会返回 403」的按钮是 bug。永远不信客户端传来的 scope 字段（`company_id` / `hall_id` / `owner_id`）。

### S3 — 破坏性操作必须先确认
删除 / 移除 / 清空 / 重置 —— 任何丢数据的动作，必须走该项目的共享确认对话框，
并**说清楚会丢多少**。原生 `window.confirm` 不算。

### S4 — 一个机制，不要每页重造
共享组件、共享工具函数已经存在时，新代码重造一份 = 评审 finding。
颜色来自 token，不写死 hex。

### S5 — 密钥不进仓库、不进客户端、不进日志
service-role key、AI token、keystore 密码一律走环境变量 / secret store。
密码只存哈希，明文绝不落库、绝不打日志。

### S6 — 不留半成品
你的改动造成的孤儿 import / 变量 / 函数，自己清掉。
**但不要顺手删你没碰过的既有死代码** —— 发现了就说一声，别自己动手。

### S7 — 外科手术式改动
只碰必须碰的。不「顺便改进」相邻代码、注释、格式。匹配既有风格，哪怕你有别的偏好。
每一行改动都要能直接追溯到用户的要求。

### S8 — 文档与代码同步
改了规则或流程，同步改 `CLAUDE.md` / `golden-rules/` / 大脑正本。
**用户可见的改名止步于 API 边界** —— 屏幕上改叫法，不等于要把数据库列名、API 字段一起改。

### S9 — 领域知识不许被「精简」掉
本标准要求文件短。**短的办法是搬家，不是删除。**
踩过的坑、口径为什么是这样、当初排除了什么 —— 这些搬进 `docs/MASTER_PROMPT.md`，
一个字都不能丢。删掉来之不易的领域知识是最严重的违规。

## 工作方式（W1–W4）—— 每一次 agent 运行都适用

这四条是为了减少 LLM 写代码时最常犯的错。琐碎任务上自行判断，但**不要拿「这个很小」当跳过的理由**。

### W1 — 先想再写
不要假设，不要藏起困惑，把取舍摆出来。动手前：说清你的假设；有多种解读就都列出来，不要默默选一个；
有更简单的做法就说；有不清楚的地方**停下来问**，不要猜着往下做。

### W2 — 简单优先
解决问题的最小代码，不做任何投机性的东西。没要求的功能不做，一次性代码不抽象，
没人要的「灵活性 / 可配置」不加，不可能发生的场景不写错误处理。
**写了 200 行但其实 50 行能做完 —— 重写。**
自问一句：**「一个资深工程师会不会说这写复杂了？」** 会 —— 就简化。

### W3 — 外科手术式改动
只碰必须碰的（同 S7）。你的改动造成的孤儿自己清，既有死代码发现了就说一声、别动手（同 S6）。
判据：**每一行改动都要能直接追溯到用户的要求。**

### W4 — 目标驱动
把任务变成可验证的目标：「加校验」→「先写非法输入的测试，再让它过」；
「修 bug」→「先写一个能复现的测试，再让它变绿」；「重构 X」→「确保重构前后测试都过」。
多步骤任务先给一句话计划，每步带验证方式。**成功标准够硬，你才能自己循环到完成**；
「让它能跑」这种软标准只会逼出反复的追问。

## 评审输出格式

按严重度排序：**正确性 / 安全（S2、S3、S5）> 功能完整性 > 整洁与层次（S4、S6、S7）**。
每条 finding 必须给出：具体的失败场景 + 金律编号 + 文件:行号。
